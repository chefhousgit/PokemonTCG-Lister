# PokemonTCG-Lister Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Railway-ready Express + React inventory/listing/fulfillment app that is fully usable with mock/manual adapters, a local Windows agent, and real PTCGPB account-JSON import.

**Architecture:** FSC-shaped monorepo (CommonJS Express + Vite JSX client) plus Postgres (PGlite locally). Marketplace and trade execution are swappable interfaces. Importer parses PTCGPB files at rest only. Agent long-polls outbound.

**Tech Stack:** Node ≥18, Express, express-session, pg, PGlite, React, Vite, Tailwind, exceljs, multer, @anthropic-ai/sdk, node --test, Railway.

**Spec:** `docs/superpowers/specs/2026-08-22-pokemontcg-lister-design.md`

## Global Constraints

- CommonJS on the server; JSX (no TypeScript) in `client/`
- No heavy ORM; `pg` + SQL migrations only
- Never read, walk, copy, or log `Accounts/Saved/`
- Never fork, vendor, or invoke PTCGPB
- Never invent Eldorado API paths
- Never commit `.env`, agent tokens, friend codes, or real account JSON
- Job payloads: identifiers only; credential-shaped keys rejected on server and agent
- `node --test` file list in root `package.json` must stay current
- UI must work with only Mock + Manual implementations registered
- Match FSC session auth, scripts, Railway files, and visual tokens

**Files:**
- Create: `routes/utils/importers/pathGuard.js`, `pathGuard.test.js`, `ptcgpbAccount.js`, `ptcgpbAccount.test.js`, `diff.js`, `wishlist.js`, `sqliteCache.js`

- Create: fixtures under `routes/utils/importers/fixtures/` — **synthetic** JSONs matching the real shape (do not copy the user’s six files or friend codes)

**Interfaces:**
- Produces: `assertSafeImportPath(root, candidate) -> void` (throws if path would enter `Accounts/Saved`)
- Produces: `parseAccountJson(obj, filename) -> { account, pulls, marks, skipped[] }`
- Produces: `buildImportDiff(existing, incoming) -> { adds, updates, skips, retires }`

Parser rules (from recon):

1. Key = `deviceAccount` or filename stem
2. Metadata fields optional; `shinedust.value`
3. Flatten `pulls[].cards[]` counts
4. Collections: if `pulls` empty and `registeredCards` present, count those
5. `tradedCards`/`sharedCards` → reservation marks
6. Tolerate missing keys; collect skips
7. Folder scan: skip any path matching `Accounts[\\/]Saved`

HTTP:

- `POST /api/imports/preview` multipart (files or zip) → diff JSON
- `POST /api/imports/commit` with approved diff id
- Optional `POST /api/imports/local` only when `PTCGPB_ROOT` set **and** not production
